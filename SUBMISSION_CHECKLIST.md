# OpenAI Build Week Submission Checklist

## Prepared In This Folder

- `README.md` - GitHub/Devpost README draft
- `DEVPOST_SUBMISSION.md` - Devpost form copy draft
- `DEMO_VIDEO_SCRIPT.md` - 2-3 minute demo video script
- `index.html` - app source
- `styles.css` - app styling
- `app.js` - app logic
- `thisone-standalone.html` - single-file demo version
- `qa-check.js` - lightweight QA checks

## Still Needed From You

### 1. Demo Link

Choose one:

- upload the app to GitHub Pages, Netlify, Vercel, or another static host;
- or provide clear local run instructions in the repo.

Recommended for judging: public hosted demo link.

### 2. GitHub Repository

Create a repository and upload:

- `index.html`
- `styles.css`
- `app.js`
- `README.md`
- `qa-check.js`
- optional: `thisone-standalone.html`

If the repository is private, share it with:

- `testing@devpost.com`
- `build-week-event@openai.com`

### 3. YouTube Demo Video

Record a public YouTube video under 3 minutes.

Must include:

- app demo;
- audio explanation;
- how you used Codex;
- how you used GPT-5.6.

Use `DEMO_VIDEO_SCRIPT.md` as your base.

### 4. Codex /feedback Session ID

Get the `/feedback` Codex Session ID from the main project thread where most of the app was built.

Paste it into the Devpost submission form.

### 5. GPT-5.6 Evidence

OpenAI Build Week requires meaningful GPT-5.6 usage.

Before submitting, make sure you can truthfully show:

- where GPT-5.6 was used;
- how it contributed;
- how judges can verify that usage.

Update these files before final submission:

- `README.md`
- `DEVPOST_SUBMISSION.md`
- `DEMO_VIDEO_SCRIPT.md`

Do not leave the TODO language in the final submission.

### 6. Devpost Form

Fill in:

- project name: ThisOne
- track: Apps for Your Life
- tagline
- description
- demo video URL
- code repository URL
- demo URL if available
- Codex Session ID

### 7. Final Accuracy Check

Before submitting, confirm:

- the app is described as a prototype;
- the app does not claim to guarantee food safety;
- all submitted materials are in English;
- all links are public or properly shared;
- the YouTube video is public;
- the repository includes clear run instructions;
- no TODO placeholders remain.
